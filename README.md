# HR System

A learning project: a REST API for managing employees, written in Go with PostgreSQL storage and Docker Compose.

**Stack:** Go 1.27 · gorilla/mux · PostgreSQL 18 · pgx v5 (`pgxpool`) · Docker Compose

## Quick start

Requires Docker with Compose v2 and `make`. Go 1.27+ is only needed to run the API outside Docker.

```bash
git clone https://github.com/Doomed07/hr_system.git
cd hr_system
```

Create `.env` in the project root. It is git-ignored, and `make` fails without it:

```dotenv
POSTGRES_USER=hr
POSTGRES_PASSWORD=change_me
POSTGRES_DB=hr_system
CONN_STRING=postgres://hr:change_me@localhost:5432/hr_system?sslmode=disable
```

- `POSTGRES_*` create the user and database when the PostgreSQL container starts for the first time.
- `CONN_STRING` is used only by `make run`. In Docker, Compose builds its own connection string to the `postgres` service.
- Keep the values consistent across variables, and avoid `@ : / $` in the password — it is part of a URL.

Then run:

| Command                 | What it does                                                        | API URL                 |
|-------------------------|---------------------------------------------------------------------|-------------------------|
| `make service-deploy`   | Build and start PostgreSQL and the API in Docker                    | `http://localhost:8080` |
| `make service-undeploy` | Stop containers; data stays in the `pgdata` volume (`docker compose down -v` removes it) | — |
| `make db-up`            | Start only PostgreSQL                                               | —                       |
| `make run`              | Run the API locally with variables from `.env` (after `make db-up`) | `http://localhost:9999` |

In Docker, the API starts only after the database passes its health check. The `employees` table is created automatically on startup.

## API

| Method   | Path         | Request body                                   | Success                                         |
|----------|--------------|------------------------------------------------|-------------------------------------------------|
| `POST`   | `/employees` | `{"full_name": "Jane Doe", "position": "HR Manager"}` | `201` + created employee                  |
| `GET`    | `/employees` | —                                              | `200` + array sorted by `id` (`[]` if empty)    |
| `DELETE` | `/employees` | `{"id": 1}`                                    | `204`                                           |

Example:

```bash
curl -X POST http://localhost:8080/employees \
  -H "Content-Type: application/json" \
  -d '{"full_name": "Jane Doe", "position": "HR Manager"}'
```

```json
{
    "id": 1,
    "full_name": "Jane Doe",
    "position": "HR Manager"
}
```

The `id` is generated by the database; an `id` in the request body is ignored.

**Errors:** `400` — invalid JSON or wrong field type, `404` — `DELETE` with an unknown id, `500` — database error. Error body: `{"Message": "...", "Time": "..."}`.

## Database

```sql
CREATE TABLE IF NOT EXISTS employees (
    id        SERIAL PRIMARY KEY,
    full_name VARCHAR(200) NOT NULL,
    position  VARCHAR(200) NOT NULL
);
```

Open `psql` in the running container (user and database from `.env`):

```bash
docker compose exec postgres psql -U hr -d hr_system
```

## How it works

```
HTTP request → gorilla/mux → Handlers → EmployeesStorage (interface) → EmployeeRepo → pgxpool → PostgreSQL
```

Handlers depend only on the `EmployeesStorage` interface and know nothing about SQL; `EmployeeRepo` implements it with PostgreSQL queries.

```
.
├── main.go                        # connects to the DB, creates the table, starts the server
├── http_server/
│   ├── server.go                  # router, port 9999
│   ├── handlers.go                # handlers + EmployeesStorage interface
│   ├── dto.go                     # JSON structures
│   └── employee.go                # Employee model and errors
├── postgres/
│   ├── simple_conn/sql_connection.go   # pgx connection pool
│   └── sql_commands/repo.go            # EmployeeRepo: SQL queries
├── Dockerfile
├── Docker-compose.yaml            # PostgreSQL + API
└── Makefile
```
